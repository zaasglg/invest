# Компаниялар мен инвестициялық жобалар API-і

Бұл API сыртқы жүйелерге компаниялар мен инвестициялық жобаларды тек оқу
режимінде береді. Аналитика үшін тек екі `GET` endpoint бар. Дерек қосатын,
өзгертетін, өшіретін немесе жеке жазбаны ашатын endpoint жоқ.

## 1. Серверде бір рет дайындау

Жаңа кестені production серверде іске қосыңыз:

```bash
php artisan migrate --force
```

Әрбір API пайдаланушысына жеке token жасаңыз:

```bash
php artisan api-client:create "Серіктес ұйым" --expires-at=2027-12-31
```

Команда шамамен мынадай жауап береді:

```text
API client #1 құрылды: Серіктес ұйым
Token тек осы рет көрсетіледі. Қауіпсіз жерге көшіріңіз:
inv_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Token дерекқорда ашық сақталмайды және кейін қайта көрсетілмейді. Жоғалса,
жаңасын жасау керек.

## 2. API пайдаланушысына не жіберу керек

Пайдаланушыға мына үш нәрсені беріңіз:

1. Base URL: `https://СІЗДІҢ-ДОМЕНІҢІЗ/api/v1`
2. Жасалған `inv_...` token
3. Осы құжаттағы endpoint және сұрау мысалдары

Token-ді HTTPS арқылы және қауіпсіз арнамен жіберіңіз: password manager,
шифрланған мессенджер немесе ұйымның құпия дерек алмасу жүйесі. Token-ді
Git-ке, ашық чатқа немесе URL query параметріне жазбаңыз.

## 3. Авторизация

Әр сұрауда екі header болуы керек:

```http
Accept: application/json
Authorization: Bearer inv_СІЗДІҢ_TOKEN
```

`curl` мысалы:

```bash
curl "https://example.kz/api/v1/companies?per_page=50" \
  -H "Accept: application/json" \
  -H "Authorization: Bearer inv_СІЗДІҢ_TOKEN"
```

Postman ішінде Authorization түрін `Bearer Token` деп таңдап, token өрісіне
`inv_...` мәнін енгізіңіз.

## 4. Endpoint-тер

API-де дәл екі маршрут бар:

| Әдіс және маршрут | Мақсаты |
|---|---|
| `GET /api/v1/companies` | Компаниялардың аналитикалық деректері |
| `GET /api/v1/projects` | Жобалардың аналитикалық деректері |

### Компаниялар тізімі

```http
GET /api/v1/companies
```

Қолдайтын фильтрлер:

| Параметр | Мысал | Түсіндірме |
|---|---|---|
| `search` | `KAZAKHSTAN` | Атауы, БСН/БИН немесе басшы бойынша іздеу |
| `status` | `active` | `active`, `inactive`, `liquidating` |
| `legal_form` | `too` | Компанияның заңды нысаны |
| `region_id` | `23` | Аймақ идентификаторы |
| `updated_since` | `2026-08-01T00:00:00+05:00` | Осы уақыттан кейін жаңарған жазбалар |
| `per_page` | `50` | Бір бетте 1–100 жазба, әдепкісі 25 |
| `page` | `2` | Пагинация беті |

Мысал:

```http
GET /api/v1/companies?status=active&region_id=23&per_page=50
```

Әр компания тізімнің өзінде толық беріледі: реквизиттер, БСН/БИН, заңды
нысаны, тіркелу күні, қызмет түрі, аймақ, мекенжайлар, статус және жобалар
саны.

### Жобалар тізімі

```http
GET /api/v1/projects
```

Қолдайтын фильтрлер:

| Параметр | Мысал | Түсіндірме |
|---|---|---|
| `search` | `электр станциясы` | Жоба/компания атауы немесе БСН/БИН бойынша іздеу |
| `company_id` | `31` | Бір компанияның жобалары |
| `region_id` | `23` | Аймақ идентификаторы |
| `project_type_id` | `4` | Жоба түрі |
| `status` | `implementation` | `plan`, `implementation`, `launched`, `suspended` |
| `archived` | `0` | `1` — архив, `0` — архивте емес |
| `updated_since` | `2026-08-01T00:00:00+05:00` | Осы уақыттан кейін жаңарған жазбалар |
| `per_page` | `50` | Бір бетте 1–100 жазба, әдепкісі 25 |
| `page` | `2` | Пагинация беті |

Мысал:

```http
GET /api/v1/projects?company_id=31&status=implementation&per_page=100
```

Логикалық жойылған жобалар API арқылы берілмейді. Архив жобалары әдепкіде
беріледі; тек белсенді тізім қажет болса `archived=0` жіберіңіз.

Әр жоба тізімнің өзінде толық аналитикалық түрде беріледі:

- компания, аймақ және жоба түрлері;
- инвестиция, жұмыс орындары, мерзімдер және статус;
- карта геометриясы мен инфрақұрылым;
- жоспарлы және нақты өндіріс;
- кураторлар, инвесторлар және орындаушылар;
- проблемалық мәселелер.

API жауабына email мекенжайлары, жоба тапсырмалары, тапсырма есептері,
құжаттар, фотолар, файл жолдары және чат деректері кірмейді.

## 5. Пагинация жауабы

Тізім endpoint-тері Laravel стандартты пагинациясын қайтарады:

```json
{
  "data": [
    {
      "id": 1,
      "name": "Компания немесе жоба атауы"
    }
  ],
  "links": {
    "first": "https://example.kz/api/v1/companies?page=1",
    "last": "https://example.kz/api/v1/companies?page=5",
    "prev": null,
    "next": "https://example.kz/api/v1/companies?page=2"
  },
  "meta": {
    "current_page": 1,
    "from": 1,
    "last_page": 5,
    "per_page": 25,
    "to": 25,
    "total": 114
  }
}
```

Барлық деректі алу үшін `meta.last_page` мәніне дейін беттерді кезекпен
сұрау керек. `updated_since` компанияның немесе жобаның өз `updated_at`
уақытын тексереді. Байланысқан өндіріс фактісі немесе проблемалық мәселе
бөлек жаңарса, ол негізгі жазбаның уақытына әрдайым әсер етпейді. Сондықтан
сыртқы жүйе мерзімді толық синхрондауды да сақтағаны дұрыс.

## 6. HTTP қателері

| Код | Мағынасы |
|---|---|
| `401` | Token жоқ, қате, өшірілген немесе мерзімі өткен |
| `404` | Мұндай API маршруты жоқ |
| `422` | Фильтр параметрі қате |
| `429` | Бір минуттағы 60 сұрау лимиті асқан |

## 7. Token-ді жабу немесе ауыстыру

Қолданыстағы token-ді жабу:

```bash
php artisan api-client:revoke 1
```

Мұндағы `1` — token жасалғанда көрсетілген API client ID.

Token ауыстырғанда алдымен жаңа token жасап, пайдаланушы жаңа token-ге
көшкеннен кейін ескі client-ті revoke еткен дұрыс.
